### 1.3 必须遵守的约定（不遵守会出事）

1. **改数据库三步都要做**：`init-mysql.sql`（空库建库）+ `db/migration/V<版本>__*.sql`（幂等）+ `db/schema.json`（登记 requires）。
2. **同时把 `VERSION` 升到该版本**。部署脚本的 `0.2/6` 检查会在 `VERSION` 与 `schema.json` 最高版本不一致时**直接中止发布**。
   背景：曾经加了 `V2.2.1` 迁移却忘升版本，迁移被静默跳过、库缺列，答卷接口大面积 500。
   应用侧还有一道 `SchemaUpgradeService#assertNoFutureScripts`：发现「比程序新且库也没到」的迁移脚本会**拒绝启动**。
3. **加/删权限点四处同步**：
   - `server/shared/.../core/constant/PermissionEnum.java`（权限页按它动态渲染）
   - `client/src/auth/permission-codes.ts` —— **生成物**，不要手改，跑 `npm run docs:gen`
   - `init-mysql.sql` 的 `t_role` 种子（admin / teacher 的 authority 串）
   - `db/migration` 里一条幂等 `UPDATE ... WHERE ... NOT LIKE '%<code>%'`
4. 迁移只允许「加表 / 加列 / 加索引」；`DROP`、`DELETE`、无 `WHERE` 的 `UPDATE` 会被 CI 拦。
5. 不 push GitHub（除非用户当次明确要求）。

## 3. P1 · 班级资源面板：点试卷进详情 ✅ 已完成（commit e765d578）

### 3.1 问题

教学 → 学情 → 班级 → 「考试与问卷 / 题库」面板：左侧班级树，右侧一张表（名称 / 类型 / 状态 / 本班窗口 / 全局窗口 / 答卷数 / 操作）。试卷名是纯文本。
老师看不出「这是哪一套卷、里面什么题、多少分」，只能在操作列点「数据分析 / 查看答卷 / 班级链接 / 编辑 / 删除」。
「编辑」虽然能进试卷，但那是改，不是「看一眼这是什么」。

### 3.2 改这里

| 文件 | 说明 |
|---|---|
| `client/src/pages/teaching/ClassResourcesPanel.tsx` | 列表本体。列：名称 / 类型 / 状态 / 本班窗口 / 全局窗口 / 答卷数 / 操作；操作列约 520~569 行 |
| `client/src/pages/teaching/ClassAnswersDrawer.tsx` | 已有的「查看答卷」抽屉，抽屉样式照它 |
| `client/src/pages/survey/Overview.tsx` | 已有的试卷概述页，字段组织可参考 |

### 3.3 方案（纯前端，**不需要新接口**）

1. **名称列改成可点**：`render` 用 `<LinkAction onClick={() => setBriefRow(row)}>` 包住 `resourceName`。
   **题库那类（`kind='repo'`）不要加**——题库没有「一套卷」的概念。
2. **新建 `client/src/pages/teaching/ProjectBriefDrawer.tsx`**：
   - Props：`open / projectId / onClose`
   - 数据：`GET /api/project?id={projectId}`（已有，`project:detail`）
   - 内容：
     - 标题行：卷名 + 分类 + 状态 Tag
     - 统计：**计分题 N / 共 M 题**、**总分 X 分**、**答卷 Y 份**
       - 题量与总分用 `flattenSchema(project.survey)` 前端算（`DATA_TYPES` 判定数据题，`attribute.examScore` 求和）
     - 题型分布：每种题型一个 Tag（「单选 10」「多选 5」「简答 2」「签名 1」）
     - 设置摘要：考试窗口（`examSetting.startTime/endTime`）、限时（`maxSubmitMinutes`）、是否允许改答案、是否开放成绩单
     - 底部操作：`去编辑`（`/survey/{id}`）、`预览答题`（`/s/{id}?preview=1`，新标签）、`看数据`（`/survey/{id}/data`）
3. 三个操作按权限渲染（无 `project:update` 不显示「去编辑」）。

### 3.4 为什么这样做

- 复用 `GET /api/project`，不新增接口、不动后端，风险最低；
- 「预览答题」直接复用刚做的 `?preview=1`，未发布的卷也能看；
- 不把「编辑」当默认入口——老师多数时候只想确认「这套卷是不是我要的那套」。

### 3.5 验收

- 点试卷名 → 抽屉打开，显示题量 / 总分 / 题型分布 / 窗口；
- 「去编辑 / 预览答题 / 看数据」跳转正确，未发布的卷「预览答题」能打开；
- `kind='repo'` 名称不可点；
- `cd client && npm run check` 通过。

## 4. P2 · 通知公告（含「检查更新」整合） ✅ 已完成（commit e2e803c5）

### 4.1 目标

管理员发全站公告；老师发**本班**公告；师生在站内看到未读提醒。
「检查更新」发现新版本时，作为一条**系统消息**出现在管理员公告里，不再单独渲染一条独立提示。

### 4.2 数据模型（`V2.2.2__notice.sql`，幂等；`VERSION` 升 2.2.2）

```sql
CREATE TABLE IF NOT EXISTS t_notice (
  id            varchar(64)  NOT NULL,
  title         varchar(200) NOT NULL,
  content       longtext     NOT NULL COMMENT '正文富文本，入库前服务端白名单消毒',
  type          varchar(32)  NOT NULL DEFAULT 'notice' COMMENT 'notice / system_update / ai_result',
  audience      varchar(16)  NOT NULL DEFAULT 'all' COMMENT 'all / admin / teacher / student',
  scope_type    varchar(16)  DEFAULT NULL COMMENT 'NULL=全站 / class=某个班 / project=某场考试',
  scope_id      varchar(64)  DEFAULT NULL,
  pinned        tinyint(1)   NOT NULL DEFAULT 0,
  require_ack   tinyint(1)   NOT NULL DEFAULT 0,
  status        varchar(16)  NOT NULL DEFAULT 'draft' COMMENT 'draft / published / archived',
  publish_at    datetime     DEFAULT NULL,
  expire_at     datetime     DEFAULT NULL,
  create_by     varchar(256) DEFAULT NULL,
  create_at     timestamp    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_at     datetime     DEFAULT NULL,
  is_deleted    tinyint(1)   NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_notice_audience (audience, status, publish_at),
  KEY idx_notice_scope (scope_type, scope_id)
) COMMENT='通知公告';

CREATE TABLE IF NOT EXISTS t_notice_read (
  id         varchar(64) NOT NULL,
  notice_id  varchar(64) NOT NULL,
  user_id    varchar(64) NOT NULL,
  read_at    datetime    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_notice_read (notice_id, user_id),
  KEY idx_notice_read_user (user_id)
) COMMENT='公告已读记录';
```

### 4.3 管理员公告 vs 老师/学员公告：**共用表 + 分开权限**

| 维度 | 管理员公告 | 老师公告 |
|---|---|---|
| 受众 | 全站 / 全体老师 / 全体管理员 | **只有本班学员** |
| 落库 | `scope_type=NULL` | `scope_type='class'` + `scope_id` |
| 权限点 | `notice:manage:system` | `notice:manage:class` |
| 可见性校验 | 按 `audience` 过滤 | 追加「我是不是这个班的成员/老师」 |
| 默认要求已读 | 可以 | 一般不 |

**结论**：一张表 + 两个维度（`audience` / `scope`）即可，**不要建两张表**——列表、已读、过期清理逻辑完全一样。
但**权限与可见性判定必须分开**，否则老师能发全站公告。

### 4.4 权限点（四处同步，见 1.3 第 3 条）

| 权限码 | 名称 | 说明 | 给谁 |
|---|---|---|---|
| `notice:list` | 查看公告 | 站内公告列表与未读数 | admin / teacher / student |
| `notice:manage:system` | 管理全站公告 | 受众可选 all/admin/teacher/student | 只给 admin |
| `notice:manage:class` | 管理班级公告 | 只能发给「自己可见的班」 | admin / teacher |

`PermissionEnum.Group` 新增 `NOTICE("公告")`，插入位置在 `CONTENT` 之前（组声明顺序 = 前端卡片顺序）。
同时要更新 `docs/permissions.md`（如果存在该章节）与 `docs:gen` 生成的参考页。

### 4.5 接口

```
GET  /api/notice/list?current=&pageSize=&onlyUnread=
GET  /api/notice/unread-count          -> { count }
GET  /api/notice?id=                   -> 详情（顺带 mark read）
POST /api/notice/read                  body { ids: [] }
POST /api/notice/create | update | publish | archive | delete
```

**Service 层必须做的校验**（不要只靠 `@PreAuthorize`）：

- 写操作：`scope_type='class'` 时 → 需要 `notice:manage:class` **且** `classService.assertVisible(scope_id)`；
  其余（全站 / 按角色）→ 需要 `notice:manage:system`。
- 列表：先按 `audience` 过滤（`all` 所有人 / `admin` 仅管理员 / `teacher` 仅老师 / `student` 仅学员），
  再按 `scope` 过滤（`class` 要求当前用户属于该班组链，用 `UserDeptScopeService`）。
- 内容入库前过 `RichTextSanitizer`（和题干富文本同一套，防 XSS）。

### 4.6 前端

| 位置 | 改动 |
|---|---|
| `client/src/layout/BasicLayout.tsx` | 顶栏「公告」铃铛 + 未读 badge（60 秒轮询 + 窗口 focus 立即刷） |
| 新建 `client/src/pages/notice/NoticeCenter.tsx` | `/notice`：左分类（全部 / 系统更新 / 未读），右列表 + 详情 |

| `client/src/pages/system/Setting.tsx` | 「检查更新」Tab **保留**（查版本 + release notes），把「发现新版本」的提示改成「去公告中心查看」 |

### 4.7 「检查更新」怎么整合（关键取舍）

**不要把公告和更新检查合成同一个数据模型。** 更新检查是系统状态，公告是运营内容：

- 已有的更新检查任务发现新版本时 → 向 `t_notice` 插一条 `type='system_update'`、`audience='admin'`、`pinned=1`；
- 同版本只插一次（按 `title` + 版本号去重）；
- 管理员在公告中心的「归档」→ `status='archived'`，不再显示；
- 「检查更新」Tab 仍然负责手动检查与版本信息展示。

### 4.8 验收

- 管理员发 `audience=all` → 所有角色在 `/notice` 看得到，铃铛有未读；
- 老师发班级公告 → 只有该班师生看得到，别班看不到；
- 老师尝试发 `audience=all` → 403；
- 更新检查发现新版本 → 管理员公告里出现系统消息，可归档，且同版本不重复；
- 公告正文里的 `<script>` 被服务端清掉；
- 权限页出现 3 个新权限点，admin/teacher 种子串已带；
- `npm run check` + `gradlew` + `docs:check` 全绿。

### 6.2 内核要加的五个组件

| 组件 | 职责 | 关键点 |
|---|---|---|
| `AiGateway` | 统一调用入口（非流式 `complete` / `completeJson`） | 超时 120s、失败重试 2 次（指数退避）、**每用户限流** |

| `AiJobService` | 长任务（出卷可能 30~90 秒） | 完全复用 PDF 那套模型：`jobId` + 内存 `ConcurrentHashMap` + 线程池 + 24h TTL + 2 秒轮询 |
| `AiContentGuard` | AI 产出校验 | 出卷必须过：每题有 `type/title`、选择题有 `dataSource`+`children`+ 至少一个 `examCorrectAnswer`、题量与分值合计符合期望、题型配比符合期望。**校验不过直接拒绝，不要修补** |
| `AiUsageLog` | 用量记账 | 表 `t_ai_usage(user_id, scene, model, prompt_tokens, completion_tokens, cost_ms, status, error, create_at)`；出问题能查、能对账 |

### 6.3 四个内嵌场景（老师开箱即用）

**① AI 出卷**（异步，因为耗时长）

```
POST /api/ai/paper/generate   body: {
  projectId,                       // 落到哪个项目（可空：只生成不入库）
  subject, level,                  // 学科 / 级别（如「养老护理员」「五级」）
  questionCount, totalScore,       // 题量、总分
  typeRatio: { Radio: 0.4, Checkbox: 0.2, Judge: 0.2, FillBlank: 0.2 },
  difficulty: 'easy'|'medium'|'hard'|'mixed',
  requirements                     // 自然语言补充要求，如「围绕冬季四防」
}  -> { jobId }

GET  /api/ai/paper/job/{jobId}     -> { status, progress, error?, result?: { questions: SurveySchema[], stats } }
POST /api/ai/paper/apply           body: { projectId, questions }   // 写入项目 schema，需 project:update
```

前端：编辑器工具栏「AI 生成试卷」→ 参数弹窗 → 进度条 → **结果预览表（题干 / 题型 / 分值 / 正确答案）** → 「全部采纳 / 逐题采纳」→ 写入画布。
**必须预览后再落库**，不要生成完直接覆盖老师的卷子。

**② AI 改题**（同步，1~3 秒）

```
POST /api/ai/question/rewrite   body: { projectId, questionId, style: 'clear'|'neutral'|'shorter' }
  -> { suggestions: [{ text, reason }] }   // 给 3 条，老师挑一条
```

前端：题目卡片上的「AI 优化」按钮 → 侧栏展示 3 条建议 → 采纳后**写进编辑器并留 before 快照**（配合 P3 的审计）。

**③ AI 批改建议**（同步，2~5 秒）

```
POST /api/ai/grade/suggest   body: { answerId, questionId }
  -> { score, confidence, points: [{ point, hit }], reason }
```

**关键约束：AI 只给建议，不落分。** 老师点「采纳」才走已有的 `POST /api/answer/grade`。
理由：AI 判错分要老师背锅，不如把责任留在人身上，AI 只做「抄近路」。

**④ AI 学情**（同步，3~8 秒）

```
POST /api/ai/report/summary   body: { projectId, classId? }
  -> { text }
```

**只吃统计数字**（`GET /api/report/{shortId}` 的结果），**不把学员原始答卷发给模型**——隐私与成本双赢。

### 6.4 权限与限额

- 新权限点 `ai:use`（四处同步，见 1.3）。默认给 admin / teacher；学员不给（学员侧的 AI 只有答题解析，已有）。
- `AiSetting` 增加两个限额字段：`dailyTokenLimit`（全站每日，默认 200 万）、`perUserDailyLimit`（单用户每日，默认 20 万）；
  `AiUsageLog` 汇总当日用量，超限时返回明确中文提示，不再调用模型。
- 每个场景在 `AiUsageLog.scene` 里区分（`paper_generate` / `question_rewrite` / `grade_suggest` / `report_summary`），方便按场景看成本。

### 6.5 验收

- 输入「20 题、100 分、养老护理员五级」→ 生成结果题量、总分、题型配比全部符合；不合规的会被 `AiContentGuard` 拒掉并给出原因；
- 结果预览能逐题采纳，采纳后画布出现题目；
- 主观题点「AI 建议」→ 出分数与理由，老师改完保存后 `t_audit` 有 `ANSWER_GRADE` 记录；
- 超日限额后返回明确提示，不调模型；
- `t_ai_usage` 有记录，能按场景汇总。

## 7. P5 · MCP Server + Token 体系 ✅ 已完成（commit 6870f4b5，手写 JSON-RPC）

### 7.1 先看这条硬约束（会决定实现方式）✅ 前提已变化：已升到 Java 25

~~**本项目是 Java 8。** 官方 `spring-ai-mcp` 要求 **Java 17+**，**不能直接用**。~~

2026-11-17 已把后端全量迁到 **Java 25 LTS + Spring Boot 4.1.2**（commit `0cca9a4b`），
所以 `org.springframework.ai:spring-ai-starter-mcp-server-webmvc:2.0.2` 现在**可以直接用**。
实现顺序：**先试官方 starter**；只有当它在本项目栈上跑不通（依赖冲突、或者权限模型接不上现有
`@PreAuthorize`）时，才退回手写 JSON-RPC 2.0。

手写的工作量集中在三块：协议解析、工具注册、鉴权。协议本身不复杂（见下）。

### 7.2 协议要点（MCP 2025-03-26 Streamable HTTP）

```
POST /mcp    Authorization: Bearer <token>
             Accept: application/json, text/event-stream
             body: JSON-RPC 2.0

initialize   -> { protocolVersion, capabilities: { tools: {} }, serverInfo }
tools/list   -> { tools: [{ name, description, inputSchema }] }
tools/call   -> { content: [{ type: 'text', text }], isError? }
```

返回可以是普通 JSON，也可以是一段 `text/event-stream`（每条 `data: {...}`）。按客户端兼容性选 JSON 最简单。

### 7.3 Token 体系

```sql
CREATE TABLE t_api_token (
  id           varchar(64) NOT NULL,
  user_id      varchar(64) NOT NULL COMMENT '按哪个用户签发；MCP 调用的权限就是它的权限',
  name         varchar(100) NOT NULL COMMENT '给用户辨认可用：如 Claude / 我的脚本',
  token_hash   varchar(128) NOT NULL COMMENT 'SHA-256，明文只返回一次',
  scopes       varchar(500) DEFAULT NULL COMMENT '逗号分隔的工具白名单；空=按用户权限',
  expires_at   datetime DEFAULT NULL,
  last_used_at datetime DEFAULT NULL,
  revoked      tinyint(1) NOT NULL DEFAULT 0,
  create_at    timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_api_token_hash (token_hash)
) COMMENT='MCP/API 访问令牌';

CREATE TABLE t_api_idempotency (
  id          varchar(64) NOT NULL,
  user_id     varchar(64) NOT NULL,
  key_value   varchar(128) NOT NULL COMMENT '客户端传的幂等键',
  result_json longtext COMMENT '第一次调用的结果，重复调用直接返回',
  create_at   timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_api_idem (user_id, key_value),
  KEY idx_api_idem_time (create_at)
) COMMENT='MCP 写操作幂等';
```

签发：`POST /api/system/api-token`（`system:setting:update`）→ 返回**明文一次**（`sk_` + 32 位十六进制）。

> ✅ 实施修正：`t_api_token` 只存 `token_hash`（SHA-256），**没有明文片段列**，所以列表显示的是
> **哈希指纹**（哈希首尾各 4 位 + `****`），不是令牌的前后 4 位。这是有意的：库里不留任何明文线索，
> 用户靠 `name` 辨认令牌。另外实际实现还有 `GET /api/system/api-token`（列表）与
> `POST /api/system/api-token/revoke`（撤销后立刻 401）。

### 7.4 工具集（收敛到 9 个，够用且好维护）

| 工具 | 作用 | 需要的权限 |
|---|---|---|
| `sk_capabilities` | 返回当前 Token 能用哪些工具、题型清单、限制（答卷上限等） | 无 |
| `sk_project_list` | 列项目（`mode=survey|exam`） | `project:list` |
| `sk_project_get` | 读项目详情（含 schema） | `project:detail` |
| `sk_project_validate` | **只校验不落库**：题量/分值/引用/正确答案完整性 | `project:detail` |
| `sk_project_create` | 创建（默认草稿） | `project:create` |
| `sk_project_update` | 更新 schema / 设置 | `project:update` |
| `sk_project_publish` | 发布 / 停收 | `project:publish` |
| `sk_report_get` | `view=summary|questions|exam` | `project:report` |
| `sk_export_create` / `sk_export_get` | 异步导出（复用现有 jobId 模型） | `answer:export` |

每个**写**工具都要求 `idempotencyKey`；命中已有键直接返回上次结果，不重复执行。

### 7.5 验收

- `curl -X POST /mcp -H 'Authorization: Bearer xxx' -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'` 返回 9 个工具；
- `sk_project_validate` 能对一份不合规 schema 给出具体错误；
- 用同一个 `idempotencyKey` 调两次 `sk_project_create` → 只建一个项目，第二次返回同一结果；
- Token 撤销后立刻 401；
- 在 Claude Desktop / WorkBuddy 里配 `mcp.json` 能连上并列出工具（可让用户实测）。

## 10. 风险清单

| 风险 | 后果 | 缓解 |
|---|---|---|
| AI 成本失控 | 账单爆炸 | P4 的双层限额 + `AiUsageLog` 按场景统计；先给保守默认值 |
| AI 产出不合规 | 老师拿到废题 | `AiContentGuard` 强校验 + 结果**必须预览后采纳**，不自动落库 |
| MCP Token 泄露 | 别人能读写你的项目 | Token 按用户签发、可撤销、可限 scopes；写操作幂等键防重放 |
| 公告富文本 XSS | 学员浏览器被注入 | 入库前过 `RichTextSanitizer`；前端 `DOMPurify` 只是第二道 |
| 审计存敏感数据 | 合规风险 | `before/after` **只存分数/状态/权限串**，不存答案正文与个人身份信息 |
| 迁移忘升版本 | 库缺列、接口 500 | 已有 `0.2/6` 检查 + 启动 fail-fast（见 1.3） |
