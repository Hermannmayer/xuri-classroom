# 权限模型方案

> 结论先行：这套系统的权限是**两层**——「功能权限」（角色决定能做什么）和「数据范围」
> （题库/考试授权决定能对哪些做）。两件事必须分开配，混在一起就会问出
> 「给了题库权限，到底是能改还是能看」。

## 2. 两层模型：别把两件事混成一件

| 层 | 管什么 | 存在哪 | 在哪配 | 例子 |
|---|---|---|---|---|
| **功能权限** | 你能**做什么动作** | `t_role.authority`（权限串） | 系统管理 → 权限配置（角色） | `repo:list`＝能看题库列表；`repo:update`＝能改题库 |
| **数据范围** | 你能**对哪些对象**做 | `t_repo_partner` / `t_project_partner`（授权记录） | 题库列表 → 授权 / 试卷 → 协作者 | 把「育婴五级题库」授权给「5级」用户组 |

**只配一层都不行：**

- 只给功能权限、不做数据授权 → 菜单有「题库列表」，但列表是空的
- 只做数据授权、不给功能权限 → 连「题库中心」菜单都不会出现

---

## 3. 三个预设角色（建议直接「套用」，不要手勾 72 个点）

| 角色 | 能做什么 | 关键权限点 | 明确不能做 |
|---|---|---|---|
| **超级管理员** | 全部 | 后端直接认 `ROLE_admin`，不看权限串 | — |
| **老师**（42 个点） | 建考试/组卷、发问卷、管题库与题目、看答卷与报表、导出 | `project:*`（含 publish/partner）、`answer:*`、`repo:*`、`template:*`、`exercise:list`、`file:*` | 任何 `system:*`（进不了系统管理） |
| **学员**（11 个点） | 只做题：**我的考试**、刷题库、看自己的答卷 | `project:list`、`project:detail`、`exercise:list`、`repo:list/detail/book`、`answer:list/detail/upload`、`user:update`、`home` | 不能建/改/删任何东西 |

> 学员能看到的考试/题库都由**数据授权**决定：考试要把他加进协作者（`t_project_partner`），
> 题库要把题库授权给他所在的用户组。给了权限但没授权，列表是空的。

> 迁移后的实测数据：超管 78 点 / 老师 42 点 / 学员 9 点。

## 4. 「题库」这组权限到底是什么意思

这是你说的「不知道是能改还是能看」的正解，前端应当按这个表显示（P1 做进界面）：

| 权限串 | 中文语义 | 看 / 改 | 学员需要 |
|---|---|---|---|
| `repo:list` | **看题库列表**（只列表，不含题目） | 看 | ✅ |
| `repo:detail` | **打开题库、看里面的题目** | 看 | ✅ |
| `repo:book` | **练习册/错题本、开始练习**（做题入口） | 做 | ✅ |
| `repo:create` | 新建题库 | 改 | ❌ |
| `repo:update` | 编辑题库（改名、改分类、题目增删改） | 改 | ❌ |
| `repo:delete` | 删除题库 | 改 | ❌ |
| `repo:export` / `repo:import` | 导出 / 导入题库 | 改 | ❌ |
| `repo:grant` | 把题库授权给用户组 | 改 | ❌ |

同理，考试组（`project:*`）里 `list/detail/report` 是看，`create/update/delete/publish/partner` 是改。

## 5. 菜单 → 权限映射（P0 已落地）

没权限就不出现，父项在**至少一个子项可见**时才出现：

| 菜单 | 需要的权限 | 超管 | 老师 | 学员 |
|---|---|---|---|---|
| 首页 | 无（所有人） | ✅ | ✅ | ✅ |
| 我的考试 | `project:list` | ✅ | ✅ | ❌ |
| 我的练习 | `exercise:list` | ❌（管理员不做题） | ✅ | ✅ |
| 题库中心 → 题库列表 | `repo:list` | ✅ | ✅ | ✅ |
| 题库中心 → 练习册 | `repo:book` | ❌ | ✅ | ✅ |
| 系统管理 → 用户管理 | `system:user:list` | ✅ | ❌ | ❌ |
| 系统管理 → 用户组 | `system:dept:list` | ✅ | ❌ | ❌ |
| 系统管理 → 系统设置 / 权限配置 | `system:role:list` | ✅ | ❌ | ❌ |
| 系统管理 → 操作日志 | `system:log:list` | ✅ | ❌ | ❌ |

判定统一走 `client/src/auth/permissions.ts` 的 `can()`（精确串或显式 `域:*`），**和路由守卫同一套语义**——这样"看得见就能点得进"。

## 6. 标准配置流程（三步，别跳）

1. **建角色**：系统管理 → 权限配置 → 选「新建角色」→ 填名称/编码 → **选一个起点预设**（空白 / 老师 / 学员）
2. **把人放进用户组**：用户组里绑角色（一个组可以绑多个角色，用户可属于多个组）
3. **授权数据**：题库/考试授权 → 选用户组或人 + 数据范围

### 6.1 后续新增角色怎么做

角色不是写死的三个，**内置的只有 admin/teacher/student 三个「预设」，其余随便加**：

| 场景 | 做法 |
|---|---|
| 想要「只改题目、不能动考试」的人 | 新建角色 → 起点选「老师」→ 把 `project:*`、`answer:*` 关掉，只留 `repo:*` + `template:*` |
| 想要「年级组长看本组数据」 | 新建角色 → 起点选「老师」→ 留只读项（`*:list` / `*:detail` / `*:report`），把写动作关掉 |
| 想给某个班单独一套权限 | 不用建角色：建用户组 → 绑现有角色 → 授权对应题库/考试 |

新建角色后，**必须第 2 步把它绑到用户组**才会生效；直接建角色不绑人，没人受影响。

### 6.2 给「新学员只能做题刷题库」的最小配置

```
角色：学员（11 个点，含 repo:detail + repo:book + project:list/detail）
用户组：5级 → 绑定「学员」角色
题库授权：目标题库 → 授权给「5级」组，范围=查看
考试授权：试卷 → 协作者 → 添加「5级」组（否则「我的考试」里看不到）
```

## 7. 为什么学员看不到「开始答题」（逐条对照）

| 现象 | 原因 | 修法 |
|---|---|---|
| 题库列表里点不进题目 | 缺 `repo:detail` | 学员预设已补 |
| 有「开始练习」但点进去 403 | 缺 `repo:book` 或 `exercise:list` | 学员预设已补 |
| 左侧没有「我的考试」 | 缺 `project:list` | ✅ 已给学员补上（数据仍按协作者过滤） |
| 有「我的考试」但里面是空的 | 试卷没把该用户/组加成协作者 | 试卷 → 协作者 → 添加用户组 |
| 菜单整个不出现 | 用户没绑任何角色 | 按 §6 配角色 |

> 学员看考试的数据范围走的是 `t_project_partner`（协作者），所以**必须把学员或他的用户组加进试卷协作者**，
> 否则他拿到了 `project:list` 也只能看到空列表。这是"功能权限"和"数据范围"两层配合的典型例子。

## 9. 后端硬结论（做任何权限改动前必须知道）

这些是读代码确认过的，不是推测：

| # | 结论 | 影响 |
|---|---|---|
| 1 | 权限串**只有精确匹配**，父级不放行子级（`project` ≠ `project:list`） | 角色里那些光秃秃的 `project` / `repo` 是历史脏串，留着无害但没用 |
| 2 | 目录里 **14 个权限点后端根本没接线**（`PermissionEnum` 标 `suggested=true`，全仓零 `@PreAuthorize`） | 勾了不生效，必须从界面删掉或标灰 |
| 3 | 三个**同名不同义**的坑：`answer:restore`（实际用 `answer:update`）、`user:import`（实际用 `system:user:create`）、`system:setting:update`（接口只认 `hasRole('admin')`） | 按名字勾权限会得到"勾了没反应" |
| 4 | 数据权限只有「项目成员」一维（`t_project_partner`）；`DataPermissionTypeEnum`（部门/岗位维度）是空壳 | 「按用户组限制能看到哪些考试」目前做不到，需要新写 |
| 5 | 用户组有效期（`valid_from/valid_to`）**只拦登录，不参与权限计算** | 组过期后已登录的人仍持有权限，最长到缓存过期（`userCache` TTL 1 天） |
| 6 | 题库的"能不能看/改"由功能权限决定；"能看哪个题库"由 `t_repo_partner` 授权决定 | 就是两层模型，别混 |

**14 个未接线的权限点（建议 P2 直接删）**：
`project:publish`、`project:partner`、`answer:audit`、`answer:restore`、`repo:grant`、`template:export`、
`exercise:manage`、`user:import`、`user:export`、`system:setting:update`、`system:log:export`、
`system:backup`、`system:restore`、`content:protect`
