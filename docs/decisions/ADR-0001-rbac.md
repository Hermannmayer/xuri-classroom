# ADR-0001 权限模型

## 状态

已接受（2026-11）。

## 背景

系统同时有「用户」「用户组/班级」「角色」「权限点」四个概念。早期实现允许用户组直接挂权限串，导致同一个角色在不同组里能力不同，审计和排障都很困难。

## 决策

1. **权限点只挂角色**，不挂用户组。
2. 用户组只负责：成员、绑定角色、有效期、数据授权。
3. 最终功能权限 = 用户直挂角色 ∪ 所属组（主组 + 附加组，沿祖先链）绑定角色 ∪ `ROLE_*` 标记。
4. 数据可见范围是另一条轴：`t_project_partner` / `t_repo_partner` / 组链；有功能权限不代表能看所有数据。
5. 组角色变更后清空 `userCache`，否则最长 1 天不生效。

## 后果

- 「角色」是可复用的能力模板；「组」是人和数据范围。
- 新增角色后，用户组和用户管理立刻能选到（不需要再配一套组权限）。
- 排障顺序：先看用户直挂角色，再看组链角色，最后看数据授权。

## 不变量

- 非管理员给组绑角色时，只能绑自己已有权限的子集；不能把 `admin` 角色绑到组。
- 组有效期过期会导致组内成员无法登录。
