# 重写 SurveyKing 前端：可行性评估

## 一、结论

**可行，而且比预想的顺。**

原因不是「逆向很顺利」，而是三件事刚好凑齐：

1. **后端 100% 开源、接口稳定** —— 新前端不需要后端改一行，只要命中同样的 `/api/*`
2. **前端闭源，但你手上就有完整产物** —— 你这台 `192.168.0.2:201` 的 101 个 chunk 已全部抓下并美化
3. **数据结构有权威定义** —— `SurveySchema.java` 567 行就是完整规范，不用从前端猜

真正的成本不在「不知道要做什么」，而在**问卷设计器**和**规则表达式引擎**这两块必须重写的硬骨头。

## 三、三条路线

### 路线 A：把产物还原成源码，再改

- 做法：用 webcrack / 手工 AST 还原成可读 TSX，补回依赖后尝试编译
- 现实：**不建议**。能还原到「读得懂」，很难到「编译得过」——样式模块、动态 import、Formily schema 构建、webpack 私有运行时都需要逐个补
- 适用：只想改几个文案或样式

### 路线 B：用 Formily 重建设计器（**推荐**）

原前端本来就是 Formily + AntD 4 + dva。用同一套栈重建，等于「照着规格重写」，不是「黑盒猜」。

- 表单/联动：Formily 直接覆盖
- 设计器：拖拽 + 属性面板，按 `SurveySchema.Attribute` 字段逐个做
- 规则引擎：**自己写**（这是必做项，见下）
- 收益：心智模型与原作者一致，遇到问题可回产物对照

### 路线 C：换一套现成问卷前端，做数据模型适配

用 SurveyJS Creator、XIAOJUSURVEY 等成熟开源设计器，写 `SurveySchema ↔ 对方 DSL` 的双向转换层。

- 优点：设计器、渲染器、条件逻辑引擎**全部白送**，可能是最快的路
- 缺点：两套 DSL 的语义不可能完全对齐（矩阵题、NPS、跨问卷关联、考试计分都是个性化很强的部分），转换层会越写越厚；且原后端的部分能力可能用不上
- 适用：只要能建普通问卷，不追求 1:1 复刻

**建议**：核心场景走 B；如果想先快速看到能跑的东西，用 C 做 MVP，再逐步替换。

## 四、工作量拆解（相对值）

以「一个人、熟悉 React」为基准，只看相对体量：

| 模块 | 体量 | 说明 |
|---|---|---|
| 基础设施（路由/请求/鉴权/布局/i18n） | 小 | 规格完全清楚，照 `architecture.md` 抄 |
| 系统管理 6 页 | 小 | 标准 CRUD + 树 + 权限矩阵 |
| 项目/题库/练习 | 中 | 列表、树、导入导出 |
| **问卷设计器** | **极大** | 原产物 21 556 行、935 KB，含拖拽、属性面板、逻辑编排、主题、模板 |
| **规则表达式引擎** | **大** | 前端专有，需从 0 实现词法/求值/题型语义；且必须与原逻辑逐条对齐（存量问卷依赖它） |
| 答题渲染器（32 题型） | 大 | Formily 能省一部分，但矩阵/级联/上传/评分/NPS 都要单独做 |
| 数据表 + 公式列 | 中 | 自定义列、导出、回收站 |
| 报表图表 | 中 | 按题型选图、交叉分析 |
| 移动端/微信 | 中 | 微信授权、字号兼容、移动布局 |

**最大风险不是写不出来，是「规则表达式引擎」与存量问卷的兼容性。** 你现在的实例是空的（0 问卷 / 0 考试），这条风险当前接近零——这正是重写的最佳时机。

## 五、必须先决策的三个问题

1. **要不要 1:1 复刻设计器？**
   如果只是自用、问卷不复杂，可以砍掉主题、模板、矩阵题，工作量能降一大截。
2. **账号体系沿用还是重做？**
   后端是 Spring Security + Cookie + XSRF 双提交，新前端照抄即可，不建议改。
3. **是否保留微信/百度统计等外部依赖？**
   `index.html` 里注入了百度统计，微信相关逻辑散在多个页面，可以整体裁掉。

## 六、建议的推进顺序

1. **搭骨架**：路由表 + 请求封装 + 登录 + 布局（`architecture.md` 直接可用）
2. **打通读写**：项目列表 → 问卷设计器（先做 3 种基础题型：单选/多选/填空）→ 保存
3. **答题闭环**：公开答题页 + 提交 + 数据表
4. **补齐题型**：按 `SurveySchema.QuestionType` 逐个加
5. **规则引擎**：先做 `visibleRule` / `jumpRule`，再补计算与校验
6. **报表与移动端**

每步都能独立验收，不必一次做完。
